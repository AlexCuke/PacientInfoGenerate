# Облтех — тестовый пациент, версия 0.4.0

Расширение Chrome/Edge для локальной генерации и копирования синтетических данных пациента.

## Установка и обновление

1. Распакуйте ZIP в постоянную папку.
2. Откройте `chrome://extensions` в Chrome или `edge://extensions` в Edge.
3. Включите «Режим разработчика».
4. Нажмите «Загрузить распакованное расширение» и выберите папку `patient-generator`, содержащую `manifest.json`.

При обновлении существующей установки замените файлы в прежней папке расширения и нажмите «Обновить» (круговая стрелка) на его карточке.

Значок расширения — белый силуэт пациента с плюсом на бирюзовом фоне. Чтобы видеть его на панели, закрепите «Облтех — тестовый пациент» в меню расширений браузера.

## Использование

Откройте расширение, при необходимости выберите пол и возраст (14–100 лет) и нажмите «Сгенерировать пациента». По умолчанию пол случайный, возраст — 18–80 лет.

Кнопка ⧉ копирует одно поле, «Копировать всё» — всю карточку. Последняя карточка сохраняется в памяти сессии браузера и доступна после закрытия всплывающего окна. После перезапуска браузера создаётся новая.

В версии 0.1.1 удалены автозаполнение формы, замена существующих полей, настройка CSS-селекторов, метка «M99 · Самотёк» и нижний информационный блок. Разрешения доступа к вкладке и выполнения скриптов удалены. Осталось только разрешение storage для памяти сессии.

## Данные и сверка

Генератор создаёт полные реквизиты паспорта, 16-значный полис ОМС с контрольной цифрой по алгоритму ТФОМС и тестовый телефон в формате `+79XXXXXXXXX`.

Галочка «Сверенный» неактивна: подключения к ЕРЗЛ и ЕРП нет. Контрольные цифры СНИЛС и ОМС рассчитываются, но это не подтверждает существование номера и его принадлежность человеку. Совпадение с реальными номерами возможно. Используйте данные для тестового контура.

Дата рождения согласована с полным возрастом на текущую дату Москвы, день рождения выбирается среди 1–28 числа. Выдача паспорта моделируется около возрастной отметки 14/20/45 лет, не позже текущей даты. Серия и орган выдачи условные; паспорт и ФИО не проверяются на существование.

Источники алгоритмов:
- https://www.nalog.gov.ru/RN77/TAXATION/insprem/
- https://rostov-tfoms.ru/services/zasedaniya-rabochih-grupp/erp/enp-struct

Генерация работает локально. Данные карточки хранятся в chrome.storage.session.

## Регистрация стационарного случая

1. Сгенерируйте карточку и раскройте «Госпитализация» в окне генератора.
2. Выберите контур из настроек elastic_new — M99 DEV, M99 ТПАК или M15. Для нового пациента выберите последовательность подготовки. Если у вас уже есть готовый черновик, введите его Process ID.
3. В разделе «Настроить сотрудника и отделение» проверьте реквизиты. Исходные значения взяты из шаблона elastic_new. Кнопка «Сохранить для контура» запоминает настройки выбранного контура в браузере.
4. Нажмите «Госпитализировать» и подтвердите отправку. Запросы выполняются в фоне. При повторном открытии окна генератора отображаются статус и ответы сервиса.

Для нового пациента расширение отправляет `POST /prepare`, затем `POST /erzl` и `POST /erp` либо `POST /synchronize`, после чего выполняет `PUT /draft` и `POST /register`. При вводе Process ID выполняется только `POST /register`. После отправки вкладка показывает Process ID и ответы сервиса. При ошибке цепочка останавливается на соответствующем шаге.

## Проверка генератора

Node.js 20 и новее:

```text
node --test tests/core.test.cjs
```

Проверяются форматы, контрольные суммы, возраст, пол и согласованность дат на 2000 карточках.
